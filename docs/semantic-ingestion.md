# Semantic Ingestion — Operations Guide

Vertex-native semantic ingestion for the Hermes memory layer: discover
allowlisted Obsidian notes and clean Git repositories, chunk them, embed with
Vertex `gemini-embedding-001`, store citation-bearing chunks in BigQuery, and
surface them to the agent as a **separate, fail-open document channel** that
never disturbs existing Memory Bank behavior.

This guide covers the architecture, the source policy, the CLI, cost reporting,
promotion semantics, migration from the old whole-note command, **rollback**,
and troubleshooting.

> Phase 1 adds **no new database or vector service**. Personal/conversational
> memory continues to live in Vertex AI Memory Bank; citation-bearing documents
> live in BigQuery tables inside the existing `hermes_memory` dataset (US).

---

## 1. Architecture and channel separation

Two memory channels stay strictly separate. They are retrieved independently and
merged only at prompt-assembly time.

| Channel | Backend | What it holds | Retrieval |
|---|---|---|---|
| **Memory Bank** | Vertex AI Memory Bank (managed) | Personal / conversational memory — durable facts and preferences distilled from turns | `RetrieveMemories` semantic search, scoped `{user_id, agent_name}` |
| **Documents** | BigQuery `hermes_memory.document_sources` / `document_chunks` (US) | Citation-bearing document chunks from Obsidian notes and clean Git repos | Exact brute-force COSINE `VECTOR_SEARCH` over active, tenant-scoped chunks |

### Ingestion pipeline

```
Obsidian vault ──┐
                 ├─► source discovery ─► chunking ─► Vertex embedding ─► BigQuery
Git repo (clean)─┘   (allowlist-first)   (structural  (gemini-embedding-  document_sources
                                          / symbol)    001 @768 dims)      document_chunks
                                                                              │
                                                          (opt-in) ──► Vertex Memory Bank
                                                                       (durable principles only)
```

- **Chunking** — Markdown is chunked structurally (by heading/section). Code is
  chunked **symbol-aware via the Python stdlib `ast`** (no tree-sitter). Chunk
  sizing is governed by config: target `600`, min `250`, max `900`, overlap `80`
  tokens (all configurable).
- **Embedding** — `gemini-embedding-001` at **768 dimensions**, with
  `auto_truncate=False` so an over-long input **fails loudly** instead of being
  silently truncated. Document embedding uses task type `RETRIEVAL_DOCUMENT`;
  query embedding uses `RETRIEVAL_QUERY` (or `CODE_RETRIEVAL_QUERY` for code).
- **Storage** — Each chunk carries a stable citation, source identity, and
  revision so retrieval is auditable. Source lifecycle (active/inactive
  revisions) lives in `document_sources`.
- **Retrieval** — Exact brute-force COSINE (`use_brute_force:true`). See
  [Limitations](#8-limitations-truthful-scope): there is **no vector index**.

### The plugin document channel (fails open)

The `gcp_memory_bank` plugin adds a **separate citation-aware document channel**
to its per-turn prefetch. It is additive and defensive:

- Enabled **by default only when the document tables are importable/available**;
  an explicit `document_retrieval_enabled` config value always wins.
- The document query embedder is built only at plugin `initialize()` time. If it
  cannot be built, documents stay inert and **Memory Bank recall is never
  blocked**.
- If document retrieval errors or times out, prefetch **fails open** to Memory
  Bank — the turn proceeds with conversational memory alone. Documents never
  block or degrade the existing behavior.
- Document hits are injected under a `### Documents` sub-section with each line
  retaining its explicit `[citation]`.

## 2. Source policy

Discovery is **allowlist-first with default-deny**. A file is ingested only if it
matches the allowlist *and* survives every deny rule.

- **Allowlist-first** — Obsidian ingestion defaults to Markdown only
  (`*.md`, `*.markdown`, `*.mdown`, `*.mkd`). Anything not on the allowlist
  (e.g. `.obsidian/` config, attachments) is **rejected**, not silently ingested.
  Repository ingestion is scoped by `--include`/`--exclude` globs.
- **Default-deny for sensitive/derived content**, by both path and content:
  - **Secrets** — secret-looking paths (e.g. `*secret*`, credential files) and
    secret-looking content (API keys, tokens, private keys) are rejected.
  - **Generated files** — `generated/` dirs, `*.generated.*`, `@generated`,
    `<auto-generated>`, "do not edit … generated by" markers.
  - **Checksums** — `.md5/.sha1/.sha256/…/.sum` and `checksums`/`*sums.txt`.
- **Binary files** are rejected.
- **Hardlink fail-closed** — the reader opens each file through a contained
  descriptor and **fails closed** (raises rather than reads) if a path escapes
  the root via symlink/hardlink tricks. Discovery never follows a link out of
  the allowlisted tree.
- **Clean Git only** — repository discovery resolves Git state and refuses a
  dirty working tree unless you explicitly pass `--allow-dirty` (see
  [Troubleshooting](#7-troubleshooting)). Citations bind to the resolved commit
  SHA so they open the exact file/line range.

Every rejected file is reported (path + rule) in the plan/report so the operator
can see *why* something was excluded — bodies are never printed.

## 3. CLI

Installed as `hermes-memory` (see `pyproject.toml` `[project.scripts]`).
All ingestion is **preview-first**: without `--apply`, no BigQuery / Vertex /
Memory Bank client is constructed and **no network call is made**.

### init — create dataset + tables + views (idempotent)

```bash
hermes-memory init --project "$PROJECT_ID" --location us-central1 --bq-location US
```

### ingest-obsidian — preview then apply

```bash
# Dry run (preview only; no client constructed, no writes)
hermes-memory ingest-obsidian \
  --user tojo --agent hermes \
  --vault ~/Vaults/Hermes_Agent \
  --limit 5 --json

# Apply the first five new/changed notes
hermes-memory ingest-obsidian \
  --user tojo --agent hermes \
  --vault ~/Vaults/Hermes_Agent \
  --limit 5 --apply --json

# Apply AND distil durable principles into Memory Bank (opt-in; requires --apply)
hermes-memory ingest-obsidian \
  --user tojo --agent hermes \
  --vault ~/Vaults/Hermes_Agent \
  --apply --promote-to-memory-bank

# Deactivate sources no longer present in the vault (requires --apply; not with --limit)
hermes-memory ingest-obsidian --user tojo --agent hermes \
  --vault ~/Vaults/Hermes_Agent --apply --prune
```

- At least one `--vault` is **required** (there is no default vault allowlist).
- `--limit N` caps new/changed sources for bounded pilots; it is deterministic
  (sources ordered by relative path). `--prune` cannot be combined with
  `--limit` — a limited run has not seen the whole vault and must not deactivate
  what it did not examine.
- `--batch-chars` is **deprecated and ignored** (semantic chunking replaces
  manual batching); passing it prints a warning.

### ingest-repo — clean Git repository ingestion

```bash
# Preview a clean checkout at an explicit ref
hermes-memory ingest-repo \
  --user tojo --agent hermes \
  --repo /path/to/checkout --ref HEAD \
  --limit 20 --dry-run

# Apply
hermes-memory ingest-repo \
  --user tojo --agent hermes \
  --repo /path/to/checkout --ref HEAD \
  --limit 20 --apply
```

Repository ingestion runs through the same `IngestionPlan` path as Obsidian.
Repository sources remain retrieval chunks by default (promotion to Memory Bank
is Obsidian-default; see below). A dirty tree is refused unless `--allow-dirty`.

### search-docs — retrieve citation-bearing chunks

```bash
hermes-memory search-docs \
  --user tojo --agent hermes \
  --query "how should agents decide what becomes memory?" \
  --corpus hermes-agent-vault \
  --top-k 5
```

Embeds the query (`RETRIEVAL_QUERY`, or `CODE_RETRIEVAL_QUERY` for code intent),
runs the exact brute-force COSINE `VECTOR_SEARCH`, and prints ranked excerpts
with stable citations. `--json` emits deterministic output for tooling.

### evaluate-docs — measure against the pilot gates

```bash
hermes-memory evaluate-docs --queries evaluation/queries.yaml --json evaluation-result.json
```

Exits non-zero if the pilot gates are not met (see below). This is a **pilot
gate, not a global SLA**.

> **Note.** `init`, `ingest-obsidian`, `search`, `evaluate-docs`, `remember`,
> `stats`, `sync-local`, and `seed` are shipped. `ingest-repo` and `search-docs`
> land in the same semantic-ingestion release wave (repository + retrieval
> verbs); the invocation shapes above are their contract. If a verb is missing
> in your build, `hermes-memory --help` lists what is installed.

## 4. Cost reporting

Every plan and apply report prints a **rough, body-free cost estimate** derived
only from the token count:

```
chunks=…  requests=…  tokens=…  cost_estimate=$0.000000
```

- The estimate uses a single transparent constant
  (`_EMBEDDING_COST_PER_MILLION_TOKENS = $0.15` per 1M embedding tokens) and is
  an **estimate only** — it never implies actual billing.
- Preview reports the same estimate as apply would incur, so you can size a run
  before spending anything.
- **GenAI credit eligibility must be checked in GCP Billing.** This project does
  **not** assert credit coverage — confirm in the Billing console before
  assuming any run is free.

BigQuery storage/scan for these tiny tables is negligible (dataset is well under
100 MB); on-demand query cost dominates only for very large corpora.

## 5. Promotion semantics (Memory Bank)

Promotion distils **durable personal principles** from approved chunks into
Memory Bank — it is deliberately conservative:

- **Opt-in** — nothing is promoted without `--promote-to-memory-bank`, which
  itself requires `--apply`. A dry run never promotes.
- **Obsidian-default** — only personal Markdown notes are promotable by default.
  Code/repository sources remain retrieval chunks (they generally should not
  become "principles"); promoting them requires a separate explicit opt-in.
- **Provenance-honest** — promoted text carries the real source type/path/heading
  and instructs generation to retain only durable user preferences/principles,
  **never** transient document wording or invented citations.
- The apply report's `promotion_status` is truthful for that run:
  `not_requested` (or requested-but-nothing-eligible), `complete`, or
  `incomplete` (at least one source could not complete promotion).

## 6. Migration from the old whole-note command

The previous behavior batched **whole notes** by character count. Semantic
ingestion replaces that with structural/symbol-aware chunking:

- **Command compatibility is retained.** `ingest-obsidian` is still the entry
  point; the old `--batch-chars` flag is accepted but **deprecated and ignored**
  (it prints a warning). Manual batching is gone — chunking is automatic.
- **Preview-first is now the default.** Runs without `--apply` only plan; the old
  implicit-write behavior is gone.
- **Legacy notes are NOT auto-re-promoted.** Migrating does not retroactively
  re-embed or re-promote anything already in Memory Bank or BigQuery. To bring an
  existing vault onto the new path, run `ingest-obsidian` explicitly (start with
  `--limit` + dry-run, then `--apply`). An unchanged source that is re-run
  performs **zero** embedding/write calls (revision-aware skip), so re-ingesting
  is safe and cheap.

## 7. Rollback

Rollback is staged from **least** to **most** destructive. The first step is
always sufficient to stop document retrieval; the table steps are last-resort and
gated on explicit approval.

### Step 1 — Disable the document channel (reversible, no data loss)

Set the plugin config flag. Memory Bank behavior is **completely unchanged**.

```yaml
# ~/.hermes/config.yaml
memory:
  gcp_memory_bank:
    document_retrieval_enabled: false
```

With this false, the plugin builds no document query embedder and injects no
document context — the turn loop runs exactly as it did before documents existed.
No tables are touched; re-enable at any time by removing the flag or setting it
`true`. This is the recommended rollback.

### Step 2 — Stop ingesting

Simply stop running `ingest-obsidian --apply` / `ingest-repo --apply`. Existing
chunks remain queryable (until Step 1 disables the channel) but nothing new is
written.

### Step 3 — Deactivate / remove document tables (EXPLICIT APPROVAL ONLY)

Removing `document_sources` / `document_chunks` is **destructive and requires
explicit approval**. Both tables are protected in Terraform:

```hcl
deletion_protection = true
lifecycle {
  prevent_destroy = true
}
```

- `terraform destroy` / removal will be **refused** by `prevent_destroy` until
  the guard is intentionally lifted — this is by design.
- Prefer **logical deactivation** (marking source revisions inactive so they
  drop out of retrieval) over dropping tables. That preserves the audit trail.
- Only after explicit sign-off should anyone relax `deletion_protection` /
  `prevent_destroy` and remove the tables. **This guide does not perform DDL.**

The `memories` / `sessions` / `memory_revisions` tables and Memory Bank itself
are unaffected by document rollback at every step.

## 8. Troubleshooting

| Symptom | Cause / fix |
|---|---|
| **Model quota / auth errors** on embed | You lack quota or Application Default Credentials for Vertex. Run `gcloud auth application-default login`; confirm the model/region quota for `gemini-embedding-001` in the project. Apply runs need real creds; dry runs never call Vertex. |
| **BigQuery "dataset not found" / location mismatch** | The dataset is **US** (multi-region). Ensure `BQ_LOCATION=US` and that `init` created `hermes_memory` in US. A dataset created in a single region (e.g. `us-central1`) will not match. |
| **"repository is dirty" / refuses to ingest** | Repository discovery requires a **clean** tree so citations bind to a real commit. Commit/stash, or pass `--allow-dirty` to ingest the working-tree state (citations then reflect the dirty read, not a pushed SHA). |
| **Unsupported parser language** | Symbol-aware chunking is **Python-only** (stdlib `ast`). For any other language the chunker **falls back to line-window chunks** — ingestion still works, just without symbol boundaries. Go symbol-awareness is **deferred** (not shipped). |
| **Stale source revisions / retrieval shows old content** | Retrieval only returns **active** revisions. Re-run `ingest-obsidian`/`ingest-repo --apply` to write the new revision; a changed file replaces only its own chunks. Use `--prune` (Obsidian, non-`--limit`) to deactivate sources removed from the vault. |
| **Embedding "batch too large" / one-input-per-request** | Vertex's docs describe **interface-dependent batch limits**: the generic online guide permits multiple inputs, while the legacy `:predict` shape allows only **one** `gemini-embedding-001` input per request. The adapter binds to one SDK interface and stays correct at **one input per request** (concurrency, not batching, is used for throughput). If you see batch-limit errors, this discrepancy is why — do not assume a larger batch. |
| **Truncation warnings** | `auto_truncate=False` is intentional: an over-long input errors instead of silently truncating. Reduce `chunk_max_tokens` or split the source; never re-enable auto-truncate for citation-bearing content. |
| **Documents not appearing in prefetch** | Expected when tables are absent or `document_retrieval_enabled=false`. The channel fails open — check the plugin log line `document_retrieval=…` at init. Memory Bank recall is unaffected. |

## 9. Limitations (truthful scope)

- **Symbol-aware chunking is Python-only.** Every other language falls back to
  line-window chunks. Go (and all non-Python) symbol-awareness is **deferred**,
  not shipped. Do not claim broader language support.
- **No vector index.** Retrieval is **exact brute-force COSINE**
  (`use_brute_force:true`) over the scoped chunk set. This is correct and simple
  for a personal-scale corpus but scales linearly; there is no ANN index.
- **Phase 1 adds no new database or vector service** — documents reuse the
  existing BigQuery dataset.
- **Pilot gates, not global SLAs** — the initial pilot targets are
  Recall@5 ≥ 0.80, citation validity = 1.00, truncation = 0, and warm p95 ≤ 1.5s.
  These gate the pilot; they are not a promised production SLA.
- **Credit eligibility is unverified here** — confirm GenAI credit coverage in
  GCP Billing before assuming a run is free.
